# GitHub 全局云存档（2.4）

## 一个存档是整个项目库

入口只有「项目库 → 云存档」。一个存档包含软件的全部项目，包括每份剧本里的角色、地点、场景组、对白、描述、分支和备注；没有单项目同步按钮。

由用户明确选择四种操作：

| 操作 | 行为 |
| --- | --- |
| 新建云存档 | 先保存当前未保存改动，再把全部项目存入一个有名称、备注、时间的新存档 |
| 覆盖存档 | 明确选择一个存档，用当前本机整库覆盖该槽位；即使内容相同也按用户操作提交 |
| 读取整库 | 预览存档内的项目清单并确认，用存档替换整个本机项目库；本机多出的项目不会合并 |
| 删除存档 | 只删除选中的云存档及索引，不改本机项目或其他存档 |

不会自动比较本地／远端版本、判断谁更新、选择上传或下载，也不自动合并。启动、普通保存和打开项目都不触发云端写入。

读档前保存当前改动并保留完整本机项目库。可在「本机读档备份」预览和读取原库；目录在项目库同级的 `项目库备份-时间-标识/`。旧文件、原本的自动备份和回收站都保留在该目录。进程若在替换目录中断，重启时从恢复记录回到完整的库。新的项目库代次阻止旧的 WebView／原生编辑草稿在读档后复活。

允许读取零项目的存档，清空当前项目列表前同样需要明确确认并保留原库；重启不会重新塞入示例项目。

## 连接与授权

沿用以前的私有 GitHub 数据仓库与本机 Token。默认分支 `main`，默认目录 `xuxian/projects/`。同一仓库可供其他软件使用，彼此使用独立目录。

1. 仓库保持私有，创建时添加 README，确保分支存在。
2. 在「云存档 → 连接设置」填写仓库、分支、目录。
3. Fine-grained Token 只授权这个数据仓库的 **Contents: Read and write**，Metadata 保持只读，Account 权限留空。
4. Token 只填软件，不提交到仓库或 Actions Secrets。Windows 使用系统凭据管理器，Android 使用 Keystore 加密凭据；新设备单独配置授权。

新方案仍使用同一 Contents 权限，不需要新增 Actions Secrets。断网或权限错误时保留本机文件；不会自动改用另一个版本。每次操作检查私有状态。

## 格式、并发与边界

每个槽位由两个文件构成：

- `library-随机标识.xuxian-save.json`：`format: xuxian.library-save`、版本 1、名称、备注、存档时间，以及所有 `{ fileName, project }` 项目项。
- 对应 `.xuxian-save.meta.json`：小型列表索引，包含名称、时间、项目数及数据 blob SHA，避免列存档时下载每个完整库。

项目本身继续使用 JSON v4，兼容读取 v1–v3。文件名只允许普通相对 JSON 名称，禁止路径穿越、保留名称和重复文件名。单项目沿用 25 MB 上限，整库存档上限 50 MB。存档不包括软件授权、连接设置或素材文件；剧本里填写的资源名称／路径作为项目数据保留。

存档数据与索引通过 Git Data API 在同一次提交中更新。以当前树为基础，只修改配置目录内选中的槽位；分支引用只能快进，不强制覆盖，因此共享仓库的其他软件文件与提交不会被抹掉。

覆盖／删除／读取时携带用户预览过的 SHA。目标在确认期间被其他设备更改，或仓库同时有新提交时，只提示刷新后手动重试，不自动选择版本。此处是防止写错目标的并发保护，不是旧版的自动同步判断。

GitHub Contents 目录最多返回 1000 项；一个存档占两个文件。达到上限时需在 GitHub 手动清理或换用独立目录。

## 从旧版迁移

旧的 `项目ID.story.json` 云端文件保持原样。「旧版云端项目合集」将目录内这些项目作为一个整库清单预览，用户确认后手动读入，再可新建命名存档。不会自动迁移、删除或重新同步旧文件。

## 实现与验证

- `crates/story-store/src/library.rs`：完整捕获、校验、目录替换、恢复记录、整库备份及草稿代次。
- `crates/github-sync/src/archives.rs`：显式整库槽位操作与旧版合集读取。
- `crates/github-sync/src/http.rs`：认证、原子 Git 提交、数据校验和非强制引用更新。
- `src/application/archive-service.ts`：仅执行用户选择的存档／读档／删除，不包含自动方向判断。
- `src/editor/github-sync.js`：全局存档、预览、确认和本机备份界面。旧版自动同步 IPC 写入口返回停用提示。

验证覆盖多项目完整保存、整库替换及可恢复备份、取消、网络错误、目标变化、其他软件目录保留、原子提交、路径限制、空库、中断恢复和读档后的旧草稿隔离。
