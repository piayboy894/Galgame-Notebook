# 叙线场景编排设计

## 目标和术语

让编剧按场景组织剧本，复用地点设定，并能随时找到正在编辑的源文件。

- 地点预设属于项目，与角色并列。它定义可复用的地点名称、背景、BGM、环境音、备注和自定义属性。
- 场景组属于某一份脚本，是一段连续内容的真实容器。它包含组名、地点引用、本段备注、属性覆盖和有序的行。
- 同一地点可以用于多个场景组；例如「书房初访」和「书房对质」都引用「旧书房」，后一组可单独覆盖 BGM。

## 文件操作

编辑器提供「打开源文件所在文件夹」，定位并选中当前关联的 JSON。未保存草稿提示先保存；另存后定位新副本。项目列表的文件夹入口继续打开项目库目录。桌面原生层根据已建立的文件关联定位，页面不提交任意磁盘路径。

## 行操作

行号、空白区的右键菜单和行末菜单共用命令。插入以所点行为锚点，提供「在上方插入／在下方插入 → 对白／描述」。新对白沿用锚点的角色，插入后聚焦新行，每次操作可一步撤销。输入框中的文字选择保留系统文本菜单。

## 场景组规则

1. Ctrl/⌘+G 将同一脚本容器内的连续选中行建立为场景组；剧情阶段、调查物品脚本和单个选项内脚本均适用。
2. 组可命名、备注、折叠、复制、移动、解除和删除；解除分组保留全部内容与顺序。
3. 首版采用单层组，跨容器或嵌套建组会提示调整选择；分组不改变剧情分支和章节解锁关系。
4. 组内行继续支持插入、编辑、选择、复制、删除和排序；整组排序保持组内顺序。
5. 同项目复制保留地点引用；跨项目复制携带所引用的地点设定，并重新生成内容 ID。
6. 组标题不计入原有脚本行数。阅读与 Markdown 导出呈现场景名、地点、有效演出属性和备注。

## 地点与属性

地点通过稳定 ID 引用，改名会同步显示。场景属性按「本组显式覆盖 → 地点默认值」解析；未设置表示继承，显式空值表示清空。自定义属性采用唯一名称和值，支持后续增加演出元数据。属性先作为写作元数据保存，不自动播放或执行资源。

删除被引用地点时提示引用数量，需先替换引用；不会静默丢失场景信息。地点引用、组结构及属性统一纳入保存、撤销、复制和格式校验。

## 格式与验收

新数据采用 JSON v4。兼容读取 v1–v3，保存时迁移；旧程序会拒绝新格式，保护新增信息。升级前及保存前沿用现有备份机制。

验收覆盖源文件定位、上下插入、普通／调查／选项内建组、解除与撤销、组内和整组排序、跨项目复制、地点继承和覆盖、旧格式迁移、保存重开及 Markdown 导出。完成后发布 2.1.0，通过程序内更新获取。
